# 研究生科研打法手册

> 这是 SKILL.md 的展开层：按"卡点"组织，不按学科组织。每条都给出可执行动作和话术。
> 用法：先定位学生卡在哪一格，只读对应小节，不要把整本手册倒给用户。

---

## 0. 痛点地图：他说的，和他真正卡的

| 学生原话 | 真实卡点 | 先做什么 | 千万不要 |
| :--- | :--- | :--- | :--- |
| "导师让我先看看这个方向" | 没有可证伪的问题 | 先写 3 个候选 RQ，再做撞题检索 | 立刻读 50 篇，读完更慌 |
| "这个方向好像被人做完了" | 分不清"做完了"和"做腻了" | 找最近 3 篇的 limitation/future work | 马上换题 |
| "实验做不出来" | 没有失败判据，只能无限调参 | 补实验卡：对照、停止条件、失败判据 | 继续调参 |
| "结果不显著" | 可能数据泄漏、划分错误、baseline 太强 | 按排查顺序查一遍，报告效应量 | 反复换指标直到显著 |
| "组会不知道讲什么" | 没有决策请求 | 结论 + 一张图 + 一个请求 | 按时间线念流水账 |
| "导师说创新性不够" | 没说出"以前不知道什么" | 用贡献句式重写，不用形容词 | 加"显著""领先" |
| "论文写不出来" | 还没写三句摘要 | 先写问题/做法/结果数字 | 从引言第一句硬憋 |
| "还有三个月毕业" | 没算最小路径 | 倒推 + 砍范围 + 先保毕业 | 开新坑 |
| "想换方向" | 可能是逃避当前卡点 | 区分"方向错"和"这一步难"，设 2 周检查点 | 冲动换题 |
| "导师不管我" | 没有主动管理预期 | 每周三行周报 + 每月一次选择题 | 消失，等导师来找 |

**一句话诊断法**：让他用一句话说"我这周要交什么"。说不出来，问题在目标；说得出来但做不动，问题在方法；做得动但不想做，问题在动机或资源。

**第一句怎么接（示例）**：

- "导师让我先看看这个方向。" → "先别读 50 篇。你现在缺的是 3 个能证伪的候选问题，先用 30 分钟做一次撞题检索。"
- "实验做不出来。" → "先别调参。把实验卡写出来，尤其是失败判据；八成出在划分、泄漏或 baseline。"
- "导师说创新性不够。" → "他不是让你加形容词，是要你说清'以前不知道什么'。用贡献句式重写一句。"
- "还有三个月毕业。" → "先算毕业最小路径，砍到能答辩的范围；理想路径等有余量再说。"

## 1. 选题：从大方向到可做题目

### 1.1 四维拆分

把导师给的大方向拆成四个维度，做笛卡尔积，然后杀掉大部分：

| 维度 | 问法 | 例子（可穿戴压力识别） |
| :--- | :--- | :--- |
| 对象/场景 | 对谁、在哪、什么时候 | 大学生自习 / 考试周 / 实验室 |
| 变量/因素 | 什么影响结果 | 个体差异 / 昼夜 / 活动干扰 |
| 方法 | 用什么技术路线 | 手工特征 + 树模型 / 深度 / 迁移 |
| 评测 | 怎么算成功 | 被试内 / 跨被试 / 跨场景 / 可解释 |

规则：**每个维度至少换一次，组合出 9–12 个候选，再用三闸口杀到 3 个。** 不要从"我想用 Transformer"出发，那是方法找问题。

### 1.2 缺口从哪里来

优先从这四类里找，而不是从"没人做过"里找：

1. **设定不真实**：论文假设用户愿意戴 5 个传感器 / 标注 10 万条 / 场景无干扰。
2. **评测不全**：只做被试内，不测跨被试；只报准确率，不报校准和延迟。
3. **成本太高**：方法有效但推理要 8 张卡，实际部署不了。
4. **机制不清**：知道有效，不知道为什么有效，换个数据集就崩。

对应的缺口句式：

> 现有工作主要在 {场景} 用 {方法} 解决了 {问题}，但在 {约束} 下 {指标/可用性} 明显下降；目前还没有 {你的设定} 下的系统评测。

### 1.3 撞题怎么办

撞题不等于换题。按代价从低到高：

| 做法 | 代价 | 什么时候用 |
| :--- | :--- | :--- |
| 换约束（跨被试、低资源、隐私、实时） | 低 | 方法已有，设定没覆盖 |
| 换评测（更严格划分、校准、鲁棒性） | 低 | 原论文评测薄弱 |
| 换数据/场景 | 中 | 有独特数据或场景 access |
| 复现 + 扩展（replication + extension） | 中 | 结果可疑或没人复现过 |
| 换问题 | 高 | 上面的路都堵死 |

**复现也是贡献**：如果一篇重要论文没人复现过，你做严格复现并指出边界条件，这是合法的"新证据"型创新。

### 1.4 三个候选题目怎么呈现给导师

不要问"老师我做什么"，给选择题：

```markdown
老师，关于 {大方向}，我看了最近的文献，整理了三个可做的点：

A. {题目 A}：{一句话做法}。优点是 {…}，风险是 {…}，大概需要 {资源/时间}。
B. {题目 B}：… 
C. {题目 C}：…

我倾向 A，因为 {理由}。您看方向对不对？如果 A 的风险您觉得不可接受，我先做 B 的预实验。
```

导师最烦的是开放题，最喜欢的是"有推荐项的选择题"。

### 1.5 选题卡

用 [artifact-templates.md](artifact-templates.md) 的选题卡，一页写完。**写不满一页，说明还没想清楚，不要开始做。**

## 2. 读文献：读得快、记得住、写得出

### 2.1 三遍读法（带时间盒）

| 遍 | 时间 | 只回答 | 产出 |
| :--- | :--- | :--- | :--- |
| 第一遍 | 5 分钟 | 这篇和我有关吗？ | 标题 + 一句"它能帮我什么"，不相关就扔 |
| 第二遍 | 30 分钟 | 问题、方法、数据、指标、结论、局限 | 5 格卡片（见下） |
| 第三遍 | 2 小时 | 我能不能复现/借用/攻击它 | 方法细节、公式、代码链接、可复用模块 |

规则：**80% 的论文只配第一遍。** 只有和你的 RQ 直接相关的 10–15 篇值得第二遍，3–5 篇值得第三遍。

### 2.2 单篇卡片（5 格）

```markdown
- 问题：它要解决什么？（一句）
- 方法：核心洞察是什么？（不是模型名，是"它假设了什么"）
- 证据：数据/指标/对照，结论有多强？
- 局限：作者自己承认的 + 你看出来的
- 与我的关系：支撑我 / 反对我 / 给我 baseline / 给我数据 / 无关
```

### 2.3 引用链代替关键词漫游

1. 找 1 篇最相关的 **seed paper**（导师推荐 / 最新综述 / 高被引）。
2. **后向**：读它的参考文献，找它站在谁肩上。
3. **前向**：查谁引用了它（Google Scholar / Semantic Scholar / Connected Papers）。
4. 重复 2 层，通常会收敛到同一个圈子。

工具：Zotero + Better BibTeX 管条目与引用键；Connected Papers / Semantic Scholar 看引用链；Google Scholar 设关键词提醒。工具只负责记，判断仍要你自己做。

**饱和判据**：连续 10 篇没有出现新概念、新方法、新数据集，就停。继续读的边际收益已经很低。

### 2.4 检索式

工程/社科通用结构：

```
("stress detection" OR "stress recognition")
AND ("wearable" OR "wristband" OR "physiological")
AND ("cross-subject" OR "generalization" OR "in-the-wild")
```

- 同义词至少 3 组；中英文各查一轮（CNKI/万方 + Web of Science/Scopus/PubMed/arXiv）。
- 时间：近 5 年为主 + 3–5 篇奠基性经典。
- 记录检索式、数据库、时间范围、命中数——写综述和开题都要用，也是学术规范。

### 2.5 综述三段式（不要按时间罗列）

每一段都按"他们怎么做 → 为什么不够 → 我怎么做"：

> 早期工作多用 {方法 A} 在 {设定} 下取得了 {效果}【文献】。但这类方法假设 {假设}，在 {你的约束} 下会 {失效方式}【文献/经验】。因此本文改用 {方法 B}，在 {设定} 下直接优化 {目标}。

**不要写**："A 等人提出了……B 等人改进了……C 等人进一步……"——这是流水账，不是综述。

## 3. 开题、中期、答辩：把逻辑链说圆

### 3.1 七句逻辑链

开题报告和答辩 PPT 都按这七句展开，每句一页：

1. **现象**：现实中发生了什么，为什么值得研究。
2. **缺口**：现有研究没解决什么（引 2–3 篇最接近的，逐条说差异）。
3. **问题**：所以本文要回答什么（1 个主问题 + 2 个子问题）。
4. **假设**：我猜答案是什么（必须可证伪）。
5. **方法**：怎么验证（数据、实验、对照、指标）。
6. **证据**：什么结果算支持，什么结果算推翻（提前写）。
7. **贡献**：做完之后，谁知道什么以前不知道的。

**检验**：把七句连起来读，如果第 3 句不能从第 2 句推出来，逻辑链就是断的。评委一定会在这里问。

### 3.2 贡献怎么写

不要写形容词，写"认知增量"：

- ❌ "提出了一种高精度、鲁棒的压力识别方法"
- ✅ "首次在跨被试、自然场景下系统评测了 {方法}，发现 {结论}；并给出 {数据集/基线}，使后续工作可直接比较"

三个合法句式：

1. "本文首次在 {条件} 下证明/发现 {结论}。"
2. "本文给出 {数据/代码/基线/评测协议}，让 {问题} 可以被比较。"
3. "本文发现 {A} 与 {B} 的权衡关系，并给出 {适用边界}。"

### 3.3 评委 12 问（提前准备答案）

1. 你的问题和已有工作到底有什么不同？
2. 为什么是这个场景？换一个场景还成立吗？
3. 方法的关键改动是什么？消融能证明它有用吗？
4. 数据从哪来？样本量够吗？伦理审查过了吗？
5. 为什么选这个指标？它和真实需求对齐吗？
6. 跨被试/跨场景/跨数据集还能用吗？
7. 失败案例是什么？错误长什么样？
8. 计算成本多少？别人能复现吗？
9. 你的结论在什么条件下不成立？
10. 和最简单的 baseline 比，提升有多大？显著吗？
11. 如果给你多一年，你会做什么？
12. 全文最核心的一张图是哪张？用一句话讲清楚。

答不上来的题，就是开题后要补的实验，不是答辩时现编。

### 3.4 中期与答辩的诚实策略

- **失败也是结果**：把"没做出来"写成"在该设定下方法 A 不成立，原因是 X"，比硬凑结果可信。
- **边界比全能更加分**：明确说"我的方法只在 {条件} 下有效"，评委会认为你懂行。
- **不要藏**：评委会问的问题，你越藏他越问；主动放一页"局限与未解决"。

### 3.5 答辩/中期 PPT 的 12 页骨架

| 页 | 内容 | 这一页只回答 |
| :--- | :--- | :--- |
| 1 | 标题 + 一句话结论 | 我做了什么，结论是什么 |
| 2 | 问题 | 为什么值得做 |
| 3 | 缺口 | 别人没解决什么 |
| 4 | 方法总览 | 我的关键洞察（一张图） |
| 5 | 数据与实验设置 | 凭什么说评测是公平的 |
| 6 | 主结果 | 最重要的一个发现 |
| 7 | 消融 | 哪个模块真的有用 |
| 8 | 失败案例/边界 | 什么时候不成立 |
| 9 | 与最接近工作的对比 | 我差在哪、强在哪 |
| 10 | 贡献 | 以前不知道什么，现在知道了什么 |
| 11 | 局限 | 我诚实面对的问题 |
| 12 | 下一步 | 如果继续做，做什么 |

规则：**第 1 页就放结论**；每页一个观点；字少图大；预演 3 次并计时。答辩不是把论文念一遍，是让评委在 10 分钟内相信你知道自己在做什么。

## 4. 实验：先能证伪，再谈性能

### 4.1 实验卡（写不完不许跑）

| 字段 | 要写什么 |
| :--- | :--- |
| 假设 | 我预期什么？可证伪的句子 |
| 自变量 | 我改什么（方法/超参/数据规模） |
| 因变量 | 我测什么（指标、单位、方向） |
| 对照 | 和谁比（经典 / SOTA / 简单强基线） |
| 样本/数据 | 从哪来、多少、怎么划分、有没有泄漏 |
| 停止条件 | 跑多少次/多久就停，不许无限调参 |
| 失败判据 | 什么结果算失败（提前写，防止自欺） |
| 资源 | GPU/时间/标注成本 |
| 记录 | 日志、种子、环境、数据版本 |

### 4.2 baseline 三件套

1. **经典方法**：这个领域 5 年前的标准做法。
2. **当前 SOTA**：最近 1–2 年最强，且**你能复现**的。
3. **简单强基线**：逻辑回归 / 最近邻 / 规则 / 上一版方法。

规则：**先跑通简单强基线，再跑你的方法。** 如果简单基线已经很强，你的贡献叙事要改——这不是坏事，是提前发现。

### 4.3 结果不对的排查顺序

按这个顺序查，不要跳：

1. **数据泄漏**：预处理/归一化/特征选择有没有在划分前做？被试/受试者有没有跨集合？
2. **标签**：标注规则一致吗？有没有错标/漏标？
3. **划分**：随机划分 vs 被试划分，结果差异是否合理？
4. **baseline 实现**：官方代码？超参？有没有偷偷用测试集调？
5. **指标**：类别不平衡？阈值选错？只报 accuracy？
6. **超参**：学习率、正则、早停；固定随机种子跑 3 次。
7. **假设**：以上都没问题，可能假设本身不成立——这是最有价值的发现。

### 4.4 负结果怎么写

负结果不是"失败"，是"边界条件"：

> 在 {设定} 下，{方法} 相比 {baseline} 没有显著提升（效应量 {x}，95% CI {…}）。进一步分析表明，原因是 {机制}；当 {条件} 满足时，方法才有效。

这比硬编一个显著结果更可能通过审稿，也更安全。

### 4.5 资源不够的降级路径

| 缺什么 | 降级方案 | 代价 |
| :--- | :--- | :--- |
| GPU | 公开小模型 / 云端按小时 / 缩小规模 | 结论外推受限，需声明 |
| 数据 | 公开数据集 / 合作 / 合成 / 少样本 | 场景匹配度下降 |
| 被试 | 实验室现有数据 / 先做可行性小样本 | 统计功效不足 |
| 设备 | 手机传感器 / 开源硬件 | 精度与生态差异 |
| 标注 | 弱监督 / 主动学习 / 小规模双人标 | 噪声上限 |

降级不是丢人，**在论文里写清楚降级和边界，是加分项**。

## 5. 写作、投稿、返修

### 5.1 先写三句摘要

在写任何一节之前，先写这三句：

1. **问题**：我们解决什么问题，为什么难。
2. **做法**：我们怎么做，关键洞察是什么。
3. **结果**：我们做到了什么，用数字（没有数字就写"在 X 上验证了 Y"）。

三句写不出来，说明研究还没成型，不要开始写引言。

### 5.2 故事线

```
gap（别人没解决）→ insight（我的关键想法）→ method（怎么实现）
→ evidence（实验证明）→ limitation（边界）→ conclusion（所以呢）
```

每一节只回答一个问题：

| 节 | 只回答 |
| :--- | :--- |
| Introduction | 为什么这个问题重要且没解决？ |
| Related work | 别人做到哪，我差在哪？ |
| Method | 我的关键洞察是什么，怎么实现？ |
| Experiments | 我凭什么说它有效？ |
| Discussion | 什么情况下不成立？ |
| Conclusion | 所以呢？ |

### 5.3 选刊/选会表

| 指标 | 怎么查 | 权重 |
| :--- | :--- | :--- |
| Scope 匹配 | 最近 2 年同主题论文发在哪 | 高 |
| 审稿周期 | 官网/LetPub/学长经验 | 高（赶毕业时最高） |
| 接受率 | 官网/第三方统计（标注来源） | 中 |
| 毕业认定 | 学校/学院文件 | 高 |
| 费用 | APC/版面费 | 中 |
| 开放获取 | 是否强制 | 低 |

规则：**先定 3 个梯度（冲/稳/保），不要只投一个。** 毕业认定以学校文件为准，不要听传言。

### 5.4 Rebuttal 四段式

对每一条审稿意见：

1. **承认**：先复述你理解的问题（"We thank the reviewer for pointing out…"）。
2. **澄清**：如果是误解，给证据/位置；不要争情绪。
3. **证据**：补实验/补引用/补说明，给数字和位置。
4. **承诺**：修改后会变成什么样（"We will add… in Section X"）。

格式：一条意见一个块，原文摘要 + 回应 + 修改位置。**不要逐句反驳，不要忽略任何一条。**

### 5.5 被拒之后

先分类，再决定：

| 拒稿原因 | 处理 |
| :--- | :--- |
| 想法不新 | 换角度/换设定，或降级到 workshop |
| 实验不足 | 补对照/消融/数据集，再投 |
| 写作/表达 | 重写故事线，找同行读一遍 |
| 与期刊 scope 不符 | 换刊，不要改内容硬投 |
| 审稿人不公 | 申诉或换刊；不要在社交媒体开战 |

**不要原样转投**：至少解决一条最致命的意见，否则下一轮大概率同样结果。

## 6. 导师与组会：把"猜"变成"确认"

### 6.1 导师话术翻译表

| 导师说 | 多半意思是 | 你该做什么 |
| :--- | :--- | :--- |
| "创新性不够" | 你没说清"以前不知道什么" | 用贡献句式重写，别加形容词 |
| "再想想" | 他没看到取舍 | 给 3 个方案 + 你的推荐 + 代价 |
| "工作量不够" | 缺对照/消融/第二个数据集 | 问清补哪一块，别全面加码 |
| "这个别人做过" | 需要明确差异化 | 找 3 篇最接近的，逐条对比 |
| "你先做着看" | 他也没想清楚 | 设 2 周检查点 + 失败判据，主动汇报 |
| "数据呢" | 可行性没交代 | 补数据来源、样本量、伦理、获取周期 |
| "英语再改改" | 往往不是语法，是逻辑连接 | 先改段落主题句和连接词 |
| "最近怎么样" | 要进度，不要流水账 | 三行周报：做了什么/卡在哪/下周要什么 |
| "你自己决定" | 授权，但要你担责 | 给决策 + 依据 + 风险，事后同步 |

### 6.2 把一句话变成任务（五步）

1. **复述**："我理解您要的是 X，对吗？"
2. **交付物**：一页纸 / 一张图 / 一个实验 / 一份对比表。
3. **验收**：达到什么算完成（指标、页数、覆盖范围）。
4. **期限**：什么时候给您看。
5. **风险**："我担心 Y，需要您帮我定 Z。"

确认信模板：

```markdown
老师，我理解您希望我 {目标}。我计划 {交付物}，在 {时间} 前给您看，
验收标准是 {标准}。目前的风险是 {风险}，需要您确认 {一个问题}。
如果理解有偏差，请纠正我。
```

### 6.3 组会 10 分钟（4 页）

1. **结论**：这一周最重要的发现/判断（一句话）。
2. **一张图**：结果图或方法图，只讲这一张。
3. **卡点**：我现在卡在哪，试过什么，为什么没通。
4. **请求**：需要导师/同学给什么（数据、设备、意见、决策）。

**不要**按"我先看了……然后……又……"的时间线讲。组会是求决策，不是写日记。

### 6.4 周报三行

```markdown
本周：{完成了什么，可验收}
卡点：{卡在哪，试过什么}
下周：{要做什么，需要谁支持}
```

三行足够。连续三周不报，导师就会默认你失踪。

### 6.5 提问用选择题

- ❌ "老师，这个怎么办？"
- ✅ "A 方案快但样本少，B 方案稳但要多两周，我倾向 A，您看可以吗？"

导师的时间成本决定他愿不愿意回你。选择题降低了他的决策成本。

## 7. 时间、资源、心理

### 7.1 倒推（不要做假精确的计划）

从 deadline 往回减，用区间不用点估计：

```
投稿/答辩 deadline
− 写作与内部评审        1–2 个月
− 返修/补实验（若已投）  1–3 个月
− 主实验与消融          2–4 个月
− 预实验与数据准备      1–2 个月
− 缓冲                  总时长的 30%
= 现在必须开始的时间
```

如果算出来"现在就该开始了"，说明题目要砍，不是你要更努力。

### 7.2 毕业最小路径 vs 理想路径

| 路径 | 目标 | 取舍 |
| :--- | :--- | :--- |
| 毕业最小路径 | 满足学位要求 + 一篇能过答辩的工作 | 砍掉锦上添花的模块 |
| 理想路径 | 冲更好的期刊/会议 | 需要更多实验与时间 |

**先保最小路径，再用余量冲理想路径。** 反过来风险很高。

### 7.3 资源清单

逐项写"有 / 没有 / 能借"：数据、算力、设备、被试、编程、统计、英语、绘图、时间。缺的项就是你要提前解决的，不是开题后才发现。

### 7.4 拖延与冒名顶替

- **拖延**通常不是懒，是任务太大或标准不清。把下一步切到 30 分钟能做完，先做出一个可见结果。
- **"我不行"** 翻译成"我缺哪个具体技能/资源"：不会统计→补统计；不会写→先写三句摘要；不会做实验→先复现 baseline。多数是技能问题，不是能力问题。
- **比较焦虑**：只看自己下一个月，不看别人三年的高光。
- **方向摇摆**：每次想换方向，先设 2 周检查点，写清"如果两周内做到 X 就继续，否则再谈换"。把冲动变成实验。

### 7.5 什么时候该求助

如果持续两周以上出现失眠、食欲明显变化、无法上课、持续低落或强烈焦虑，**先找学校心理中心/校医院/信任的人**，不要靠硬扛。科研问题可以慢慢解决，健康不行。

## 8. 跨学科研究者的额外提示

如果你是交叉学科（工程 + 医学、CS + 教育、材料 + 生物）：

1. **两个圈子，两套标准**：先确认你要投的社区认什么证据（RCT？benchmark？原型？），不要用 A 领域的标准去说服 B 领域的审稿人。
2. **写一段"翻译"**：开题和论文里专门用一段解释另一个领域的术语，否则评委默认你不懂。
3. **找两个导师/合作者**：一个管方法，一个管场景；不要指望一个导师懂两边。
4. **数据与伦理先行**：涉及人、临床、教育数据，伦理审查和知情同意要在实验前，不是投稿前。
5. **贡献落在一边**：交叉工作最好在一个领域内可评价（方法贡献给 CS，场景贡献给医学/教育），不要两边都浅。

## 9. 快问快答

**Q：导师给的方向我完全不感兴趣怎么办？**
先分清"不感兴趣"和"没入门"。给自己 2 周读 10 篇，再判断。确实不想做，带着"我想做 X，因为它和组里 Y 能结合"的方案去谈，而不是空手说不想做。

**Q：没人带，怎么办？**
找一篇同方向的优秀博士论文，按它的章节结构反推你的工作；找 2–3 个同方向的师兄师姐/线上社区；把问题问到具体（"这个损失函数为什么用温度系数"），不要问"我该怎么做科研"。

**Q：英文写作很差怎么办？**
先写中文逻辑，再翻译；用短句；每段一个主题句；找母语者/润色服务只改语言，不改逻辑。逻辑不清，语言再好也没用。

**Q：实验结果和预期相反，要不要重做？**
先按排查顺序查实现和数据；都正确的话，这就是结果。报告它，并解释边界条件——这往往是论文里最有价值的部分。

**Q：投稿一直被拒，是不是我不适合科研？**
拒稿是常态，不是能力判决。把拒稿意见分类：想法、实验、写作、scope。每次只改一类，下一轮就会更好。

**Q：AI 能帮我写论文吗？**
能帮你想结构、改语言、查逻辑、模拟审稿；不能替你生成未读文献的"总结"、编数据、代写正文。用之前查学校/期刊的 AI 政策，用了就声明。
